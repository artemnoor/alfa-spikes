# T08 offline benchmark

Набор содержит 300 искусственно составленных русскоязычных новостных заметок: 30 сюжетных семейств, по 10 вариантов в каждом. Для каждой заметки заранее задана эталонная разметка темы IPTC Media Topics, события SENTiVENT, жанра IPTC и упомянутых сущностей.

**Это не результаты запуска модели и не тест нашей системы.** Генератор работает локально, без сети, API, Jev или вызова бэкенда. Сюжеты, названия компаний и люди вымышлены. Эталон отражает разметку, которую автор набора назначил этим конкретным шаблонным примерам; он не заменяет экспертную разметку реальных новостей и не доказывает качество классификатора.

## Состав

- `news.jsonl` — по одной записи на строку: `id`, `familyId`, `split`, `language`, `title`, `body`, `text`.
- `gold-labels.jsonl` — эталонная запись с тем же `id`: тема с QCode и полным путём в дереве, SENTiVENT ID и название главного/дочернего типа, жанр с QCode, сущности `type`/`text`.
- `manifest.json` — количество записей, разбиение, распределения классов и сведения об источниках таксономий.
- `build.mjs` — воспроизводимая генерация и проверка, что все метки существуют в локальных деревьях таксономий.
- `score.mjs` — простой офлайн подсчёт exact-match accuracy для предсказаний.
- `score-hierarchical.mjs` — офлайн оценка тем IPTC по пути в дереве: помимо точного QCode показывает совпадение верхнего раздела и средний иерархический F1 с частичным баллом за общих родителей.
- `run.mjs` — полный прогон через локальный API T08 и сохранение предсказаний и сбоев. Модель берётся из активной конфигурации backend.
- `runs/` — неизменяемые архивы отдельных запусков; текущий активный backend использует DeepSeek V4 Flash.
- `run-predictions.jsonl`, `run-errors.jsonl`, `run-summary.json` — временные результаты последнего прогона; для долговременного хранения запуска копируйте их в отдельную папку внутри `runs/`.

Разбиение: 210 train, 30 dev, 60 test. Оно назначается по `familyId`, до создания десяти вариантов: близкие перефразировки одного сюжета не пересекают части набора. Набор небольшой для оценки обобщения, а классы намеренно несбалансированы: распределение см. в `manifest.json`.

## Повторная генерация

Из корня проекта:

```powershell
node backend/T08/benchmark/build.mjs
```

Скрипт читает только локальные файлы таксономий из `src/blocks/T08/datasets/` и перезаписывает три сгенерированных файла. Время генерации фиксировано как `reproducible`, сами данные детерминированы.

## Формат для последующей оценки

Когда появятся предсказания от выбранной системы, сохранить их отдельно в JSONL с теми же `id`. Например:

```json
{"id":"ai-launch-01","topic":"medtop:20001298","event":"sentivent:product_service_launch","genre":"genre:Current"}
```

Затем запустить скорер из этой папки:

```powershell
node backend/T08/benchmark/score.mjs path/to/predictions.jsonl
```

Скорер сравнивает идентификаторы меток, печатает accuracy по задачам и частям, число пропусков и дубликатов. Он ничего не отправляет в модель. Для сущностей пока не считает метрику: эталон хранит упоминания без символьных офсетов, чтобы не выдавать спорные границы за точные NER-спаны.

Для более мягкой оценки только темы запустите `node backend/T08/benchmark/score-hierarchical.mjs path/to/predictions.jsonl [path/to/report.json]`. Иерархический F1 сравнивает все узлы пути от IPTC-раздела до выбранной темы: точный QCode даёт 1, общий предок — частичный балл, разные верхние разделы — 0. Одновременно печатаются строгая точность QCode и точность верхнего раздела. Широкая тема получает меньшую точность за недостаточную конкретность. Это дополнительная метрика, а не замена строгой.

Полный запуск через локальный T08 API: `node backend/T08/benchmark/run.mjs`. Он делает один запрос классификации на новость, с параллелизмом 2 по умолчанию; это обращается к настроенному провайдеру и может потреблять квоту. После завершения `node backend/T08/benchmark/score.mjs backend/T08/benchmark/run-predictions.jsonl` считает точное совпадение меток, а `node backend/T08/benchmark/summarize-run.mjs` формирует сводку с coverage, токенами и сообщённой провайдером стоимостью. Запуск не нужен для генерации самого офлайн-набора.

## Сохранённые результаты

- `runs/jev-2026-10-15/` — полный запуск Jev на этом наборе.
- `runs/deepseek-v4-flash-2026-10-15/` — полный запуск DeepSeek V4 Flash, список ошибок API и попарное сравнение с Jev. Сводка показывает результаты среди успешно обработанных новостей; ошибки исключены из знаменателя точности и отражены через coverage.

На общей части тестового разбиения, успешно обработанной обеими моделями (40 новостей), DeepSeek верно классифицировал тему в 14 случаях против 13 у Jev, событие — в 40 против 40, жанр — в 33 против 32. На всех общих успешно обработанных записях (158) Jev получил 66/158, 150/158 и 120/158 точных меток темы, события и жанра; DeepSeek — 62/158, 142/158 и 119/158. У обоих моделей покрытие тестовой части одинаковое: 48/60. Точный парный результат и полные метрики находятся в JSON архивов. Набор синтетический и имеет вручную назначенные метки, поэтому небольшая разница в несколько новостей не доказывает превосходство на реальном новостном потоке.

## Таксономии и атрибуция

- Темы: [IPTC Media Topics](https://www.iptc.org/std/NewsCodes/treeview/mediatopic/mediatopic-en-US.html), локальная копия в `src/blocks/T08/datasets/iptc-media-topics-tree-en-US.json` (CC BY 4.0).
- Типы событий: [SENTiVENT event typology](https://github.com/GillesJ/sentivent_webannoparser/blob/master/sentivent_en_event_typology.json), локальная копия в `src/blocks/T08/datasets/sentivent-event-tree.json`.
- Жанры: [IPTC Genre](https://www.iptc.org/std/NewsCodes/treeview/genre/genre-en-GB.html), локальная копия в `src/blocks/T08/datasets/iptc-genre-tree-en-GB.json` (CC BY 4.0).
- Сущности отмечены вручную по слотам генератора (`ORG`, `PERSON`, `PRODUCT`, `LOC`, `DATE`, `MONEY`). Для них здесь нет отдельного исходного датасета или универсального эталона.

В английских таксономиях сохранены исходные QCode и подписи, хотя примеры написаны по-русски. Для `no_matching_event` используется служебная запись SENTiVENT для сюжетов без события корпоративной типологии.
