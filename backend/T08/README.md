# T08 news classifier

Minimal Node.js backend that classifies a news item against IPTC Media Topics, the SENTiVENT event typology, and IPTC Genre using Polza AI. IPTC Media Topic classification keeps Jev's top-three search at every level and retains pruned branches. Jev compares up to ten final topics by path, definition, and text support. When checks signal doubt, Jev searches retained branches and adds recovered alternatives and relevant ancestors to the shortlist. DeepSeek V4 Flash receives that combined shortlist in at most one final call and can replace Jev's selection. The final result stays at the most specific category supported by the article; a parent is selected only when no narrower candidate is adequately supported. If fallback cannot complete, the Jev selection is retained. SENTiVENT event classification uses Jev's hierarchical probabilities to rank the final candidates, then DeepSeek V4 Flash returns the proposed event ID, a short exact quote, and an experimental support score in one structured response. The backend requires the quote to be an exact substring of the article; otherwise the score is set to zero. A score below the configurable experimental threshold produces `no_matching_event`. IPTC Genre uses regular Jev single-path traversal.

## Run

Node.js 22 or newer is required. Set `POLZA_AI_API_KEY` (or `POLZA_API_KEY`) in the environment. Optional settings are `POLZA_API_BASE_URL`, `T08_TOPIC_MODEL`, `T08_EVENT_EVIDENCE_MODEL`, `T08_EVENT_SUPPORT_THRESHOLD`, `PORT`, and `CORS_ORIGIN`. `T08_TOPIC_MODEL` and `T08_EVENT_EVIDENCE_MODEL` default to `deepseek/deepseek-v4-flash`; the experimental event evidence threshold defaults to `0.7`. Jev handles the topic traversal, event candidate search, and genre classification.

```powershell
npm install
npm start
```

The default API is `http://127.0.0.1:8091`:

- `GET /health` reports whether credentials are configured and how many concepts are loaded for each source.
- `POST /classify` accepts `{ "state": "...news text..." }` and returns the primary topic, business event type, editorial genre, paths, confidence signals, request count, token usage, and cost when Polza returns it. Topic confidence checks include the Jev top-two margin, per-candidate text-support scores, hierarchy agreement, retained recovery branches, and whether DeepSeek was called. The event response includes `event_type`, `evidence_text`, `support_score`, `evidence_verified`, and the proposed type if the evidence gate rejected it.

The same response now includes `classifications.entities`, produced by one DeepSeek V4 Flash request. The model returns compact rows for entity references, events, short source quotes, relations, and typed facts; the backend creates stable graph IDs and derives normalized names, legal forms, sources, fact evidence, and relation labels. `FACILITY` covers explicit physical assets such as factories, production lines, warehouses, complexes, and data centers. Predicate checks enforce endpoint types (for example, `ORGANIZATION → launches → FACILITY`, `FACILITY → located_in → LOCATION`, and `PERSON → executive_of → ORGANIZATION`) and verify that the quote supports the relation. Any entity mention, event, fact, or relation without an exact source quote is rejected. `MONEY` requires an explicit supported currency; `QUANTITY` requires a recognized measurement unit. Numeric facts carry a qualifier such as `at_most`, so “до 40 тысяч” stays an upper bound. Exact numeric facts missing from a model response can be recovered from article text without another model request. Unit and magnitude normalization happens in code, separate from money, percentage, date, and duration handling. Organizations are checked against an optional JSON client registry configured by `T08_CLIENT_REGISTRY_PATH`, then searched individually in the FNS EGRUL public interface; a captcha challenge is reported and never bypassed. FNS matches require an exact normalized name and corroborating legal form in the article; otherwise the organization stays unresolved. Foreign Latin-script organizations may also be checked against Wikidata and GLEIF, and are linked only on an exact normalized-name match. Missing or ambiguous matches remain `null`. No registry is downloaded in bulk.

SENTiVENT classification and the graph are separate fields: `classifications.event` holds its single standard category, and `classifications.entities.sentivent_classification` exposes that same result next to the detailed graph in the UI. `classifications.entities.events` contains concrete event instances, participants, and facts; each event has a deterministic `event_status` (`completed`, `announced`, `planned`, `conditional`, or `denied`) inferred from exact article evidence without another LLM request. Event-bound relations carry that same status, so an announced acquisition is not displayed as completed. If DeepSeek returns `finish_reason=length`, the backend makes no retry: it salvages only complete JSON objects where possible, otherwise returns a clearly marked grounded sentence-level fallback. Any salvaged or fallback graph, or any response with items rejected by quote/ID/unit validation, sets `status: partial`; the UI and copyable report preserve that label. Polza receives `reasoning: { effort: "none" }`, which its endpoint accepts for DeepSeek V4 Flash, plus `temperature: 0` and a 3,000-token hard ceiling. A one-article diagnostic returned 0 reasoning tokens and 294 visible JSON tokens; the saved run is linked below.

To configure a client registry, provide a JSON array (or `{ "organizations": [...] }`) with records containing `name`, optional `aliases`, `entity_id` or `id`, and optional `inn`. Entity results include input/output usage, provider-reported reasoning and visible-output token counts when available, and cost. The raw response, request, usage split, and extracted graph from the generation investigation are in `benchmark/runs/provider-raw-compact-no-reasoning-final-2026-10-16/`; the comparison and total diagnostic spend are in `benchmark/runs/provider-generation-diagnostics-2026-10-16/README.md`. The entity, object, relation, and numeric-fact run on the five sample stories is saved in `benchmark/runs/entity-graph-facilities-typed-relations-final-2026-10-16/RESULTS.md`. The earlier five-article event-status benchmark is in `benchmark/runs/entity-status-five-news-2026-10-16/`; it covers a separate status-only change. These provider requests consume Polza quota.

## Smoke check

```powershell
npm run smoke
npm run smoke-all
```

These commands send synthetic Russian news items to the configured model through Polza and save the returned classifications to `smoke-results.json` and `smoke-all-results.json`. They consume API quota and are not accuracy benchmarks.

The classifier selects one primary subject, one SENTiVENT event type (or `no_matching_event`), and one IPTC Genre per classification. Topic search uses Jev's probability distribution to keep the top three children at each expanded level and saves lower-ranked siblings in a recovery pool. Final Jev assessment compares candidate paths and definitions and checks article support with a separate yes/no question per candidate. DeepSeek is called at most once, only when the quality checks signal doubt. When support is weak, Jev ranks and reopens retained branches; the combined shortlist sent to DeepSeek includes current finalists and recovered alternatives, including ancestors where relevant. DeepSeek chooses the final topic and may replace Jev's selection. It is instructed to prefer the most specific category supported by the article and select a parent only when narrower candidates lack sufficient support. For events, Jev ranks candidates from its hierarchical path probabilities without an extra final-choice request. DeepSeek then returns the event ID, an exact evidence quote, and a support score in one call; backend code validates the quote by checking that it occurs in the source news. Scores below the experimental threshold yield `no_matching_event`. Jev is a typed decision API and does not generate free-form text, so the quote is produced by the configured evidence model rather than by Jev. Genre classification follows one Jev choice at each level. IPTC metadata can contain multiple subjects; multi-label classification needs a separate pass over candidate subjects.

## Taxonomy

The JSON tree files in `src/blocks/T08/datasets/` are generated from the downloaded source datasets. The Media Topics tree contains 1,085 active concepts; the Genre tree excludes retired concepts; SENTiVENT types are arranged by main type and subtype and include `no_matching_event`. DeepSeek receives only the current shortlist of up to ten topic finalists, never the full IPTC taxonomy.
