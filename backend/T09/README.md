# T09 — векторизация результатов T08

Сервис получает четыре текстовых блока из результата T08 — тему, тип события, сущности и характер — и отправляет их одним пакетным запросом в Polza AI Embeddings API.

Используется модель `qwen/qwen3-embedding-8b`. После векторизации PostgreSQL с pgvector возвращает топ‑10 похожих новостей по среднему cosine similarity четырёх блоков. Один пакетный запрос JEV сравнивает новую новость со всеми кандидатами и выбирает `SAME`, `RELATED`, `DIFFERENT` или `UNSURE`. DeepSeek V4 Flash вызывается только если JEV сообщает `UNSURE`, его уверенность ниже порога или ответы по кандидату и типу связи расходятся.

Итоговое действие: `SAME` → дополнить событие; `RELATED` → создать связанное; `DIFFERENT` → создать новое; `UNSURE` → ручная проверка. По умолчанию порог уверенности и минимальный разрыв кандидатов — `0.70` и `0.12`; это настраивается через `T09_MATCH_CONFIDENCE_THRESHOLD` и `T09_MATCH_MARGIN_THRESHOLD`. Порог экспериментальный, а уверенность JEV/DeepSeek не считается вероятностью фактической правильности.

При запуске PostgreSQL должен быть доступен по `T09_PGVECTOR_URL` из `backend/pipeline/.env`. Векторы хранятся как `vector(4096)`. Индекс приближённого поиска не создаётся: размерность Qwen 4096 выше ограничения HNSW для типа `vector`, а точный перебор соответствует небольшому текущему корпусу.

## Запуск

Из корня проекта запустите:

```powershell
$env:POLZA_AI_API_KEY = "ваш ключ"
npm --prefix backend/pipeline run seed
docker compose --env-file backend/pipeline/.env -f backend/pipeline/compose.yaml -p alfa-spikes-t09-pgvector up -d
npm --prefix backend/T09 start
```

Сервис слушает `http://127.0.0.1:8092`. Ключ можно задать в окружении процесса; код его не выводит. Параметры `PORT`, `POLZA_EMBEDDING_MODEL`, `POLZA_API_BASE_URL` и `CORS_ORIGIN` можно переопределить через переменные окружения.

## API

- `GET /health` — состояние Polza, PostgreSQL и число новостей, имеющих все четыре вектора.
- `POST /vectorize` — принимает `newsId`, `title`, исходные `content`, `publicationDate`, `sourceKind` и `blocks`, массив из четырёх объектов `{ key, label, text }`, где `key`: `topic`, `event`, `entities` или `genre`.

Ответ включает embeddings, краткий preview, размерность, usage токенов, `topCandidates` с десятью новостями и их оценками JEV, а также `decision` с отношением, выбранным кандидатом, уверенностью, источником решения и итоговым действием. Если кандидат не найден, новая новость получает решение `DIFFERENT` без вызова LLM.

## Тесты и живой бенчмарк

```powershell
npm --prefix backend/T09 run test:all
```

`test:all` запускает 15 тестов классификационной логики с поддельным HTTP-провайдером, 2 интеграционных теста PostgreSQL/pgvector и 7 HTTP-тестов локального API. Для интеграционных проверок нужен работающий PostgreSQL из `backend/pipeline/.env`; модельные запросы в этих тестах не выполняются.

Живой бенчмарк выполняется отдельной командой и тарифицируется провайдерами:

```powershell
npm --prefix backend/T09 run benchmark:live
```

Он отправляет контрольные новости через работающий T09, Qwen Embeddings, JEV и DeepSeek по необходимости. Отчет и сырые классификационные результаты сохраняются в `backend/T09/benchmark/runs/<run-id>/`. Контрольные истории синтетические. Каждая обработка также остается в истории `stage_runs`; временные тестовые векторы удаляются после завершения прогона, чтобы следующий запуск не сравнивался с предыдущими копиями тех же тестов.

Последний прогон: [`RESULTS.md`](benchmark/runs/2026-10-16T16-08-39-879Z-c7ed9f74/RESULTS.md) и [`results.json`](benchmark/runs/2026-10-16T16-08-39-879Z-c7ed9f74/results.json). В нем 9 из 11 отношений совпали с ручной разметкой; ожидаемая статья оказалась в top‑10 в 11 случаях из 11. JEV сделал 11 запросов, DeepSeek — 5. Зафиксированная стоимость JEV и DeepSeek составила 1,4095 ₽; API Qwen не вернул стоимость embeddings. Это синтетическая проверка, а не независимый замер качества на новостном потоке.
